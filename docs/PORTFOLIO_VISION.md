# Portfolio Vision

## Identity

Anwar Ayoon — technology-driven problem solver. Not narrowly a data scientist, ML engineer, or developer. Those are tools. The identity is: someone who notices friction in existing systems, questions why it exists, and builds practical alternatives using technology.

## 10-Second Message

> Anwar notices problems that others accept as normal, asks why they exist, investigates the underlying system, and builds practical solutions using technology.

## Conceptual Metaphor

"The Problem Solver's Notebook" — a clean digital research notebook + technical publication + interactive portfolio. Contains finished work, experiments, unfinished work, opinions, mistakes, evolving beliefs. The metaphor lives in information architecture and interaction, NOT in visual clichés (no fake paper, handwritten fonts, sticky notes).

## Current Priorities (ordered, will evolve)

1. Get interviews
2. Convince technical hiring managers
3. Impress recruiters
4. Find collaborators
5. Build credibility online
6. Attract freelance/consulting
7. Document growth
8. Start conversations with builders

Architecture must support shifting from job-search tool → lasting body of work.

## Personality

Curious, honest, playful, resourceful, technical. NOT childish, overly futuristic, corporate, sterile, template-like, resume-like, AI-generated.

## Core Philosophies (embedded throughout, never dumped as quotes)

- Build Before Perfect: Plan → Build → Observe → Refactor → Revise
- Understand Before Automating: Don't automate what you don't understand
- Context Beats Complexity: Simple + grounded > impressive + disconnected
- More Data ≠ Better Decisions: Data needs clear questions and context
- Code Has A Cost: Every line = maintenance, debugging, dependency
- Failure Is Evidence: Wrong approaches reduce uncertainty
- Constraints Create Movement: Limits improve creativity
- Problem Framing Matters: How you state the problem changes which solutions appear

## North Star

> This website should reveal not only what I built, but how and why I thought about the problem—and how that thinking changed after I built it.
