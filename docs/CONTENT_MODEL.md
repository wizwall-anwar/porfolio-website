# Content Model

## Projects (Case Studies)

Each project follows a 12-part storytelling structure. Not all parts are required for every project.

1. **The Friction** — What problem made this worth investigating?
2. **My Initial Understanding** — What I believed, assumed, expected
3. **Reframing The Problem** — How the question changed with understanding
4. **Constraints** — Dataset, compute, time, hardware, knowledge limitations
5. **Approaches Considered** — Competing approaches, tradeoffs
6. **Architecture** — System design, interactive where possible
7. **Building The Workable Version** — First functioning solution, intentional imperfections
8. **What Happened** — Metrics, outputs, failures, edge cases
9. **How My Understanding Changed** — Before / During / After comparison
10. **What I Would Change** — Specific improvements
11. **What Happened Next** — Continuation, evolution, inspiration
12. **Visitor Participation** — "What would you change?" prompt

## Notebook Entries

Short thinking pieces. Categories:
- Building
- Data & AI
- Problem Solving
- Systems & People
- Learning
- Career
- Experiments

Display: date, topic, status, related project, optional references.

## Open Notebook

Three content types:
- **Working Positions**: Things I currently believe but may revise
- **Open Questions**: Questions without settled answers
- **Lessons Under Revision**: Ideas where my opinion is changing

Each supports visitor response (moderated, not auto-public).

## Reusable MDX Components

Components available inside MDX content:
- `<ProblemStatement>` — Framed problem with context
- `<AssumptionBlock>` — What I assumed, with reveal of what actually happened
- `<ReframingBlock>` — Initial question vs. better question
- `<DecisionBlock>` — Choice made, alternatives considered, tradeoff accepted
- `<ConstraintsBlock>` — List of constraints with context
- `<ResultBlock>` — Metric or output with interpretation
- `<FailureBlock>` — What went wrong and what it taught
- `<BeforeAfterReflection>` — Before/After or I thought/Reality showed/I now believe
- `<LessonBlock>` — Key takeaway with project context
- `<Callout>` — Highlighted aside (info, warning, question)
- `<CodeBlock>` — Syntax-highlighted code with optional annotations
- `<ImageWithCaption>` — Image with structured caption
